# myTrail 기반 KTX 텔레그램 봇

## 구성과 사용자 흐름

이 버전은 myTrail의 `srtgo/bot`을 기준으로 합니다. 관리자 전용 새 봇이 아닙니다.
기존 사용자별 등록, 카드 목록·추가·편집·삭제, 검색, 페이지 선택, 반복 예매,
자동결제 카드 지정과 수동결제 흐름을 유지합니다. SRT 입력과 API는 제외했습니다.

코레일 통신은 `src/srtgo/rail/ktx/client.py`에서 기존 `pykorail` 공개 메서드로 연결합니다.
DynaPath·암호화·기기 문자열·TLS·요청 필드 구현은 pykorail을 그대로 사용합니다.
라이브러리의 성공 반환값 `None`을 기존 myTrail 결제 흐름에 맞게 `True`로 변환합니다.
관리자 터미널에서 일반 사용자의 코레일 계정이나 카드를 미리 입력하지 않습니다.

## 1. 관리자: 서버 설치

PC에서 변경을 push한 뒤 서버에서 진행합니다. 실행 중인 기존 봇은 먼저 종료하세요.
같은 봇 토큰으로 myTrail 원본과 이 봇을 동시에 실행하지 마세요.

```bash
cd ~/apps/myTrail2
git status --short
git pull --ff-only origin main
uv sync --locked --all-extras
uv run --locked --all-extras ruff format --check
uv run --locked --all-extras ruff check
uv run --locked --all-extras ty check
uv run --locked --all-extras pytest
```

서버 수정사항이나 오류가 나오면 다음 단계로 넘어가지 마세요. 자동 테스트는 실제 통신하지 않습니다.

## 2. 관리자: 운영 설정만 준비

처음 설정할 때만 아래를 실행합니다.

```bash
umask 077
cp -n .env.example .env
uv run --locked --extra bot srtgo-bot keygen
nano .env
chmod 600 .env
mkdir -p data/users
chmod 700 data data/users
```

`.env` 내용:

```dotenv
BOT_TOKEN=실제_봇_토큰
BOT_DB_KEY=생성한_Fernet_암호화키
BOT_ALLOWED_IDS=관리자숫자ID,사용자1숫자ID,사용자2숫자ID
BOT_USERS_DIR=data/users
```

- `BOT_ALLOWED_IDS`는 기존 myTrail처럼 허용 사용자 목록입니다. 등록된 사람은 누구나 자신의 계정·카드를 텔레그램에서 관리합니다. 처음에는 `BOT_ALLOWED_IDS=`로 비워 두어도 봇이 실행됩니다. 이때는 본인 ID 안내만 제공하고 계정 등록·조회·예매는 허용하지 않습니다.
- 숫자 ID를 모르는 사용자는 실행 중인 봇에 개인 대화로 `/setup` 또는 `/start`를 보내면 본인 ID와 관리자에게 전달하라는 안내를 받습니다. 관리자가 `.env`의 허용 목록에 숫자 ID를 추가하고 봇을 재시작하면 `/setup`으로 등록할 수 있습니다.
- 기존 사용자 파일을 유지할 때는 **기존 암호화 키를 유지**하세요. keygen 결과로 교체하면 기존 파일을 읽지 못합니다.
- `BOT_USERS_DIR`에는 각 사용자의 `숫자ID.json.enc`가 생성됩니다. 기존 myTrail 형식과 호환됩니다.
- 사용자 디렉터리의 상위 폴더에 작업 확인 기록과 이중 실행 잠금 DB를 저장합니다. 사용자별로 다른 저장소를 별도 봇 프로세스에 지정하면 전역 중복 방지는 되지 않습니다.
- 계정·카드·키·토큰·`data/`를 Git이나 로그에 올리지 마세요. 데이터와 키가 함께 유출되면 복호화할 수 있습니다.
- 조회 후 대기는 원본 myTrail과 같은 `gammavariate(21.08, 0.25) + 1.23`초입니다. 매번 새로 추출하며 평균 6.5초, 하한 1.23초이고 고정 상한은 없습니다. 실제 조회 시작 간격에는 조회·처리 시간도 더해집니다. 재시도 가능한 조회 오류 후에도 같은 분포로 기다리고, `/cancel`은 대기를 즉시 해제합니다.
- 이전 `BOT_POLL_SECONDS` 설정은 더 이상 적용하지 않습니다. 남아 있으면 경고만 출력하고 위 감마분포를 사용하므로 `.env`에서 제거하세요. 이는 허용된 요청 한도를 보장하는 수치가 아닙니다. 오류/차단 시 중단하고 서비스 약관을 준수하세요.

### 앞서 만든 pykorail_bot에서 전환하는 경우

이전 안내의 **서버 `setup --user`는 더 이상 사용하지 않습니다.** 일반 사용자 등록은 텔레그램에서 합니다.

- 기존 `.env`의 `BOT_ENABLE_PAYMENTS`, `BOT_MAX_PAYMENT_WON`, `BOT_MAX_MINUTES`, `BOT_DATA_DIR`는 새 봇 옵션이 아닙니다. 제거하고 위 설정으로 정리하세요. 결제 스위치를 조용히 무시하지 않도록 `BOT_ENABLE_PAYMENTS`가 남아 있으면 시작을 거부합니다.
- **이번 버전은 myTrail처럼 예약 전 카드를 선택하면 자동결제합니다.** 첫 검증에서는 반드시 **수동 결제**를 선택하세요.
- `bot-data/`가 있으면 이전 봇의 미결제·불확실한 예약을 코레일 앱에서 먼저 확인·처리하세요. 봇을 중단한 상태에서 기존 `bot-data/`를 별도의 백업 위치로 옮긴 뒤 새 봇을 시작하고 텔레그램에서 재등록하세요. 기존 데이터는 자동 변환하거나 삭제하지 않습니다.
- 기본 `bot-data/` 또는 설정한 이전 데이터 폴더가 비어 있지 않으면 시작을 거부합니다.
- 원본 myTrail의 사용자 파일을 옮길 때는 양쪽 봇을 중단하고 `data/users`와 기존 암호화 키를 함께 보존하세요. **pykorail_bot의 `users/*.enc`는 다른 형식**이므로 이곳에 그대로 섞지 마세요.

## 3. 서버 실행

```bash
uv run --locked --extra bot srtgo-bot run
```

`pykorail-bot run`도 같은 myTrail 기반 구현을 실행하는 호환 명령입니다.
실행 시 텔레그램에 연결합니다. 코레일 로그인은 각 사용자가 조회할 때 수행합니다.
PuTTY 창을 열어 두고 테스트하며, 종료는 Ctrl+C입니다. 새 인바운드 포트를 열 필요는 없습니다.

## 4. 사용자: 텔레그램에서 등록·검색

각자 봇과 **개인 대화**를 열고 `/start`, `/setup`을 보냅니다.

1. 코레일 회원번호·이메일·휴대폰번호 중 로그인 ID 입력.
2. 코레일 비밀번호 입력.
3. 카드번호 → 비밀번호 앞 2자리 → 생년월일/사업자등록번호 → 유효기간 YYMM → 카드 별칭 순서로 등록.
   카드는 첫 카드번호 질문에서 `skip`을 입력해 생략할 수 있습니다.
4. 이후 `/cards`에서 카드 추가·편집·삭제. 기존 계정 정보 변경은 `/setup`을 다시 보내 덮어쓰기를 확인합니다.
5. 등록 중 `/cancel`은 입력 취소입니다.

입력 메시지 삭제를 시도하지만 **텔레그램을 통한 전송·보관 자체가 없어지는 것은 아닙니다**.
삭제 실패 시 직접 삭제 안내를 표시합니다. 민감한 내용을 다시 출력하거나 로그에 남기지 않습니다.

검색은 기존 myTrail의 고정 형식입니다.

```text
서울 부산 20261003 0900
서울 부산 20261003 1400 KTX 특실우선
부산 서울 20261003 1000 KTX 어린이
```

날짜는 실제 미래 날짜로 바꾸세요. 모든 시각은 한국시간입니다.
좌석 옵션: 일반만(기본), 일반우선, 특실만, 특실우선.
승객 유형은 기존처럼 성인 기본 또는 어린이·유아·경로·중증장애인·경증장애인 한 명입니다.
SRT나 자연어 LLM 입력은 지원하지 않습니다. `울산`·`통도사`는 `울산(통도사)`,
`여수`·`여수엑스포`·`여수expo`는 `여수EXPO`로 인식합니다. `서울역`·`부산역`처럼
끝의 `역`도 생략해 인식하며 전각 괄호도 처리합니다. 출발·도착 양쪽에 적용합니다.
`김천`·`구미`·`광주`처럼 실제 다른 역을 뜻할 수 있는 이름이나 일반 오타는 임의로
다른 역으로 바꾸지 않습니다. 이후 pykorail의 역 마스터 검증을 그대로 거칩니다.

**조회 결과가 나오면 로그인·조회 확인은 완료입니다.** 아직 예약하지 않습니다.

## 5. 예약·결제·취소

- 열차 번호 또는 **이 페이지 전부** → 자동결제할 카드 또는 **수동 결제** 선택.
- 자동결제 시작 안내는 `예약 시도 시작. 좌석 확보 후 약 3분 뒤 자동 결제합니다.`입니다.
- 진행 중 `/status`에는 작업 시작 후 경과 초와 재조회 시도 횟수가 표시됩니다. 조회 응답 대기 중이면 몇 번째 조회인지도 표시합니다. 열차 선택 전 최초 목록 조회는 제외하며, 오류가 발생한 재조회는 포함합니다. 시간은 자동결제 대기 중에도 계속 측정하고 조회 횟수는 늘리지 않습니다. 재시작·새 작업에서는 초기화하며 사용자별로 구분합니다.
- 카드 선택은 **실제 자동결제 동의**입니다. 선택 당시 카드 정보로 좌석 확보 후 `gammavariate(36, 5)`초를 기다렸다가 결제를 시도합니다. 평균 180초(3분), 표준편차 30초이며 예약마다 한 번만 추출합니다. 예약 성공 즉시 결제 예정 시각(한국시간)을 알립니다. 이는 결제 전 지연이지 응답 제한 시간이 아닙니다.
- 코레일의 결제기한을 넘기지 않도록 대기는 **결제기한 30초 전까지 남은 시간**으로 제한합니다. 이미 그 여유가 없거나 기한을 해석할 수 없으면 자동결제를 보내지 않고 앱 확인을 안내합니다. 실제 요청 전에도 기존 예약·금액·결제기한 검사를 다시 수행합니다. 30초 여유가 결제 성공을 보장하지는 않습니다.
- 자동결제 대기 중에도 `/cancel`로 대기를 깨우고 예약을 취소할 수 있습니다. 봇 종료 시 결제 대기는 중단하며 미결제 예약 기록은 남습니다. 재시작 시 자동결제를 재개하지 않으므로 `/status`와 앱에서 확인하세요.
- 수동 결제는 좌석 확보 알림 → **결제** → 카드 선택 순서입니다. 카드 선택 시 실제 결제합니다.
- 여러 열차 선택은 모두 구매하는 것이 아니라 선택한 후보 중 한 편을 확보하는 기존 흐름입니다.
- 매진이면 재조회합니다. 기존 myTrail의 코레일 예약대기 판단도 유지하며, 대기로 등록된 건은 좌석 확보로 표시하거나 자동결제하지 않습니다.
- `/cancel`은 반복 시도를 중단하고 **이 봇에 결제 대기 중인 예약이 있으면 실제 예약 취소**를 요청합니다.
  이전 pykorail_bot의 “조회 중단만” 동작과 다릅니다. 결제된 승차권의 환불은 코레일 앱에서 하세요.
- 이미 전송한 예약 요청은 취소할 수 없으므로 응답을 기다린 뒤 중단합니다. 중단 후 도착한 예약은 자동결제하지 않습니다.
- 결과가 불확실한 예약·결제·취소는 자동 재전송하지 않고 `/status`에 확인 대기로 남깁니다.
- `/status`의 **앱에서 확인·처리 완료**는 직접 코레일 앱에서 상태를 확인하고 처리를 마친 뒤 누르세요.
  이 버튼은 봇의 확인 대기만 해제하며 원격 취소·결제·환불을 하지 않습니다.
- 재시작하면 반복 작업과 대화 중 입력은 재개하지 않습니다. 미확인 쓰기 기록은 보존하며 앱 확인이 필요합니다.

## 6. 상시 실행과 업데이트

수동 검증 후 Ctrl+C로 종료합니다. `docs/pykorail-bot.service`의 사용자·경로를 확인하세요.
`data/users`를 미리 생성해야 합니다.

```bash
sudo cp docs/pykorail-bot.service /etc/systemd/system/pykorail-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now pykorail-bot
sudo systemctl status pykorail-bot
journalctl -u pykorail-bot -n 50 --no-pager
```

이후 업데이트는 중단 → pull → 의존성 갱신 → 검사 → 재시작 순서입니다.
서버에서 소스를 수정하지 말고 PC에서 수정·검증·push하세요.
`.env`와 사용자 데이터는 업데이트 때 삭제하지 마세요.

## 검증 범위

자동 검증은 가짜 pykorail 세션과 텔레그램 객체로 수행합니다.
실제 로그인·조회·예매·승인 성공을 대신 검증한 것은 아닙니다.
먼저 본인 계정으로 **조회만** 확인하고, 이후 원하는 예약에서 수동 결제를 선택해 확인하세요.
